# 03: Фокус клавіатурою не ховається під липкими рядками

**What to build:** Тренер, який ходить Tab-ом по прокрученому списку в шторці, завжди бачить
сфокусований рядок: браузер не ховає його під ручкою шторки, полем пошуку чи
першим рядком картки. Це вимога доступності, і вона ж помітна кожному, хто
користується зовнішньою клавіатурою з планшетом.

**Blocked by:** 01 (перевіряємо на посиланнях, а не на кнопках)

**Status:** resolved

- [x] Прокрутивши список у шторці й натиснувши Tab, кожен наступний рядок повністю видно під липкими елементами
- [x] Те саме для Shift+Tab у зворотний бік
- [x] Працює в усіх трьох висотах шторки, на екрані карти (пошук) і в картці М'яза чи Вправи
- [x] Вигляд шторки без фокуса не змінився
- [x] Перевірено в браузері з клавіатурою: Tab з кінця довгого списку й назад

## Comments

**Перевірка 21.09.2026.** Автоперевірка: `scroll-padding-top` у шторці = 85.5 px. Поведінку Tab / Shift+Tab по довгому списку в трьох висотах шторки не перевіряла: лишається власникові.

**Автоперевірка 21.09.2026 (headless Chrome, справжні натискання Tab).** Екрани: карта, картка М'яза, картка Вправи; висоти: середня й висока (у низькій список прихований за задумом, у ньому нема чого фокусувати). На кожному екрані 70 натискань Tab уперед і 70 Shift+Tab назад: жоден сфокусований рядок не опинився під ручкою чи липким рядком і не вийшов за нижній край шторки (0 з 840 кроків). Контроль: із вимкненим відступом прокручування та сама перевірка ловить закритий рядок. Вигляд без фокуса не змінений: відступ прокручування впливає лише на прокрутку до сфокусованого елемента.
